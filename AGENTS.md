# AGENTS.md

## Provenance

- Standalone repo, not a fork. It began as a fork of Rompelhd's VitaSSH
  (<https://github.com/rompelhd/VitaSSH>), whose history was dropped when this became its own
  project; packaging and installation also follow TheOfficialFloW's VitaShell. Both are
  credited in README.md. Upstream is effectively unmaintained and is not a seam to keep
  clean: this repo is canonical, so fix cruft rather than working around it.

## Machine-local context

- Personal and environment identifiers — the maintainer's name, the Vita endpoints, the host key fingerprint, the devbox hostnames — live in the gitignored `CLAUDE.local.md` and nowhere else. Read it before any device run; if it is missing, ask for the endpoint rather than guessing one.
- Never write those values into tracked files, backlog task notes and commit messages included. Tasks refer to them generically (`the user`, `the home Vita`, `the work Vita`, `devbox A`/`devbox B`) and point at `CLAUDE.local.md` for the real values.

## Build

- `task` (Taskfile, <https://taskfile.dev>) is the entry point — never run `cmake` directly.
  Bare `cmake` dies with "Please define VITASDK" because CMakeLists.txt reads it from the
  environment. `task` with no args lists tasks.
- Order matters: `task setup` → `task build`. Setup builds the OpenSSL 1.1.1 Vita port, then libssh2 (the client's library), then libssh (the server's library) into `$VITASDK`. libssh2 and libssh both configure against that OpenSSL, so openssl first is required, not a preference.
- Both tasks fingerprint inputs and skip when current. After editing a portlib recipe or lib source, force: `task --force build`, `task --force setup:openssl`, `task --force setup:libssh2`, `task --force setup:libssh`. Each portlib's version is pinned by `pkgver=` in its `libs/<name>/VITABUILD`, which the matching `setup:` task reads; libssh also pins `sha256sums=` there, and `setup:libssh` refuses a tarball that does not match it. A libssh version bump therefore means updating both lines, and then checking that `libs/libssh/vita.patch` still applies, because the recipe re-extracts and re-patches on every run.
- Setup stages ~160 MB of OpenSSL/libssh2/libssh sources under `.task/portlibs` (gitignored). `task clean` wipes `build/` and `.task/` but leaves the libs installed in `$VITASDK`.
- The host-runnable checks are `python3 -I scripts/test_vpk_zip.py` (zip fixtures against `src/vpk_zip.c`, pure C plus zlib), `python3 -I scripts/test_vpk_head.py` (`src/vpk_head.c` against an independent Python transcription of VitaShell's `makeHeadBin`), and `python3 -I scripts/test_vpk_updater.py` (one-shot updater handoff, targeted shutdown, failure logging and relaunch with stubbed Vita APIs), `python3 -I scripts/test_sh_grep.py` (`src/sh_grep.c` under ASan/UBSan: BRE matching, the bounded line reader, and the step-budget refusal), `python3 -I scripts/test_vpk_policy.py` (`src/vpk_policy.c` under ASan/UBSan: title ID validity, system titles, and every verdict for thirteen title kinds against every combination of installed, running and replace, from a literal table), `python3 -I scripts/test_sh_alias.py` (`src/sh_alias.c` under ASan/UBSan: the alias table's names, bounds, sorted listing, the bash-style expansion order through other aliases with each applied once, the refusal of a definition that would close a ring, and every operation sequence up to four over three names and five values against a model), `python3 -I scripts/test_sh_chain.py` (`src/sh_chain.c` (default, custom, empty, mixed whitespace and non-whitespace), the literal-dollar and quoted-dollar bytes, the unsupported and malformed forms with the text they report, the output bound, every Its `-u` rule — one line per run of equal keys on the already sorted list, comparing keys without the byte tie-break, with the survivor the first of the run in sorted order — was pinned against `gsort` on the cases where a transitive group-by-key (keep the earliest input line) silently differs, so it must not be "tidied" into the transitive form. `python3 -I scripts/test_sh_curl_name.py` (`src/sh_curl_name.c` under ASan/UBSan: the http/https URL check and its rejected-part wording, the `-O` last-segment name, and the `-J` Content-Disposition name, where `filename*=` wins, directory parts are stripped and a name with `..`, a control byte or a FAT-illegal character is refused; swept over every string up to five bytes from a hostile alphabet and every sequence of up to four header fragments, checking that whatever comes out is a bare name), `python3 -I scripts/test_sh_wget_args.py` (`src/sh_wget_args.c` under ASan/UBSan: wget's options, clustered and spelled long, `-O -`, the refusal of `-r`, `-p` and `-m` wherever they sit, and the unknown-option, missing-operand and second-URL errors), `python3 -I scripts/test_sh_listen.py` (`src/sh_listen.c` under ASan/UBSan: the listener rebuild schedule, where the first attempt is immediate, a failed attempt waits 500 ms and doubles up to 30 s, a rebuild keeps the backoff and a good accept resets it, swept over every sequence of up to seven events against a model). Every host binary here is run under `timeout`, and exit 124 is a failure, not a pass. Everything else has no tests, lint, or CI. A successful `task build` producing both
  `build/ssh_client_vita.vpk` and `build/ssh_server_vita.vpk` is the only verification.
  Output is arm-vita-eabi (cross-compiled); nothing here builds or runs on the host.
- The server's text segment used to fail `vita-elf-create` as an abort, not a link error: `Cannot allocate N bytes for SCE data at end of segment 0; segment 1 overlaps`. The cause is page alignment, not total size: the tool appends about 3.3 KB of SCE data to the end of the read-only segment, and the RW segment starts at the next 4 KB page, so the slack left after text is whatever `text mod 0x1000` leaves (2760 bytes when libcurl was first linked, which failed, while the text grew 700 KB). `cmake/vita_seg0_slack.ld` (passed with `-Wl,-T` on the server target, `INSERT AFTER .eh_frame`) ends the segment one byte past a page boundary, which leaves 4095 bytes of slack whatever the size, and `seg0_slack_anchor` in `src/vita_shims.c` gives that section a read-only input (a section with no input becomes NOBITS and turns segment 0 into RWX, which `vita-elf-create` rejects with `Layout error: overlapping sections`). Drop either and the next code change can flip the build back to the abort. `src/sshd_builtins.c` is still compiled `-Os` (`set_source_files_properties` in CMakeLists.txt) from before this was understood; it has not been rechecked whether that is still needed. `arm-vita-eabi-readelf -lW build/ssh_server_vita` shows the two LOAD segments.
- One cmake invocation builds both apps, and `task build` exits non-zero if either fails
  to compile (make normally still produces the other app's VPK in the same pass). For a
  compile-and-link check of one app, build its **executable** target:
  `cmake --build build --target ssh_server_vita`. The `.self` and `.vpk` targets are
  stamped files — vita.cmake gives the VPK no edge on the SELF, which is why
  CMakeLists.txt adds `add_dependencies(<app>.vpk-vpk <app>.self-self)` by hand. Without
  it a VPK is packed once on a clean tree and never repacked, no matter how many sources
  change. Packages come from `task build`, never from asking make for a `.vpk`.

## Configuring VITASDK

- Resolution order: `task build VITASDK=<path>` → `.env` → `~/.local/opt/vitasdk`.
  Copy `.env.example` to `.env` (gitignored) for machine-local config. `build` fingerprints
  `.env`, so editing it re-runs cmake.
- Changing the SDK path requires `rm -rf build/` — `CMakeCache.txt` pins absolute
  toolchain paths (`CMAKE_C_COMPILER`, `CMAKE_AR`, …) from whichever value configured it.
- The root taskfile deliberately has **no `env:` block**, and it should stay that way. An
  `env:` entry sharing a name with a `vars:` key silently blocks the dotenv value from
  reaching `{{.VITASDK}}`, and `env: PATH` never applies at all — a variable already in
  the process environment outranks Taskfile env values. Instead, `build` passes `VITASDK=`
  to cmake explicitly and the portlib recipes `export PATH` themselves.
- The `| default` fallback is declared **once**, in the root `vars:`. `taskfiles/setup.yml`
  is not a usable entrypoint — `task --taskfile taskfiles/setup.yml libssh2` dies on its own
  relative paths — so the parent's vars are always in scope for the dozen or so
  `{{.VITASDK}}` expansions there. The fallback earns its keep on a blank value (e.g.
  `VITASDK=` empty in `.env`), which would otherwise install portlibs into `/arm-vita-eabi`
  and drop the toolchain off `PATH`.
- `dotenv` only works in the entrypoint taskfile: it is not supported inside included
  taskfiles, so keep it in `taskfile.yml`, not `taskfiles/setup.yml`.

## libssh portlib (the server's library)

- `libs/libssh/VITABUILD` and `setup:libssh` in `taskfiles/setup.yml` are two copies of one recipe and must be edited together. libssh is static only, built out-of-tree into a wiped directory, staged, then copied into `$VITASDK`, and the task fails if `libssh.a` is missing afterwards (a cmake configure that quietly found no OpenSSL still exits 0).
- These options look redundant or tidy-able and are not; each one has already cost a debugging cycle:
  - `-DBUILD_SHARED_LIBS=OFF` is spelled with the S. `BUILD_SHARED_LIB` is accepted by cmake as an unused variable and quietly builds the shared library anyway.
  - `-DCMAKE_POSITION_INDEPENDENT_CODE=OFF` is not enough on its own. PIC emits `R_ARM_GOT_BREL` relocations and `vita-elf-create` dies with "Invalid relocation type 25". libssh's `cmake/Modules/DefineCMakeDefaults.cmake` hard-sets the variable with a plain `set()`, which outranks the cache, so the command-line flag does nothing until `libs/libssh/vita.patch` makes that `set()` conditional. Drop the patch hunk and the flag stops working with no warning.
  - `-DHAVE_GCC_THREAD_LOCAL_STORAGE=OFF` keeps libssh's log level, log callback and userdata out of `__thread` storage. A thread made with `sceKernelCreateThread` has no TLS block, so `ssh_set_log_level()` and `ssh_set_log_callback()` look like they succeeded while libssh reads level 0 with no callback and logs nothing, ever. The server runs on exactly such a thread.
  - The rest of `vita.patch` exists because the Vita newlib has no `<net/if.h>`, no `<sys/un.h>` and no termios; libssh includes the first two unguarded and the build dies before any guard can help. `if_nametoindex()` and `sockaddr_un` are stubbed to fail at runtime on client-only paths a server never takes.
  - The `env -u CPPFLAGS -u CFLAGS …` scrub and `-DOPENSSL_ROOT_DIR` are both there because cmake reads those variables from the environment and `FindOpenSSL` will happily return Homebrew's `openssl@3`. The task asserts `OPENSSL_CRYPTO_LIBRARY` in `CMakeCache.txt` resolves into `$VITASDK` rather than trusting configure's output. Same reasoning as the libssh2 note below.
  - `-DTHREADS_HAVE_PTHREAD_ARG=NO` is passed by the recipe, but no failure from removing it has been recorded; leave it alone until someone records one.
- libssh's server side is not available to an app by linking `-lssh` alone:
  - `target_compile_definitions(<app> PRIVATE WITH_SERVER)` is required. libssh compiles the `ssh_bind_*` and `sftp_server_*` declarations out of its installed public headers unless `WITH_SERVER` is defined, and it defines that only in its own private `config.h`, so a consumer without it gets no `ssh_bind_*` and no `sftp_server_*`.
  - The libraries are `ssh`, `ssl`, `crypto`, `z` (libssh's compression path) and `pthread` (libssh's `pthread.c`; the SDK ships `libpthread.a`), plus `SceAppMgr_stub` and `SceCommonDialog_stub`. The last two look unrelated to SSH: vita2d's shared-framebuffer path references them, and omitting either breaks the link. `ScePower_stub` is the idle-timer tick that keeps the device awake while the server runs. `png` and `bz2` are deliberately absent from the server, since nothing there pulls vita2d's image loaders.
  - libssh2 and libssh never mix: the client links only libssh2, the server only libssh.

## libcurl portlib (HTTPS downloads; linked into the server)

- `libs/curl/VITABUILD` and `setup:curl` in `taskfiles/setup.yml` are two copies of one recipe and must be edited together, including the `ac_cv_*` overrides. `pkgver=` and `sha256sums=` are read by the task, and it refuses a tarball that does not match. Only `lib/` and `include/` are built and installed (no curl tool), http and https only, static only. `setup:curl` is part of `setup:portlibs`, and `libcurl.a` is a source of `task build`.
- The version is pinned at 8.17.0 because curl removed OpenSSL 1.1.1 support in 8.18.0 (its `docs/DEPRECATE.md`) and the SDK's OpenSSL port is 1.1.1. A bump past 8.17.x means moving the OpenSSL port first.
- Each override looks tidy-able and is not:
  - `ac_cv_header_stdatomic_h=no`: the SDK's `stdatomic.h` is clang's and uses `__c11_atomic_*` builtins gcc lacks, so `easy_lock.h` fails to compile.
  - `ac_cv_func_pipe2=no ac_cv_func_pipe=no ac_cv_func_eventfd=no`: configure's checks only link, the Vita libc has stubs, and the headers do not declare `pipe2`.
  - `curl_disallow_socketpair=yes`: `--disable-socketpair` only defines `CURL_DISABLE_SOCKETPAIR` and the link check still sets `HAVE_SOCKETPAIR`, so with unix sockets off `socketpair.h` stops at `#error "unsupported Unix domain and socketpair build combo"`. The `ac_cv_func_socketpair` cache variable is not what that check reads.
  - The `env -u CPPFLAGS ... PKG_CONFIG_*` scrub and `--with-openssl=$VITASDK/arm-vita-eabi` are the same Homebrew-OpenSSL defense as libssh2. The task asserts `USE_OPENSSL` in `lib/curl_config.h` and that no host path reached the flags rather than trusting configure's output.
- Settled on a device (work Vita, 2026-11-17, scratch probe on a 1 MB-stack thread, network brought up with `src/network.c`):
  - Name resolution: the blocking resolver is right. libc `getaddrinfo()` and `gethostbyname()` both resolve through sceNet with no extra setup, so no threaded resolver or c-ares is needed.
  - CA store: libcurl built without a CA path fails every HTTPS request with `unable to get local issuer certificate (20)`, so `CURLOPT_CAINFO` must always be set. `vs0:data/external/cert/CA_LIST.cer` (315 KB, concatenated PEM with `#SCEI Root CA` comment lines) verified `https://github.com/` with HTTP 200, so the system store needs nothing shipped. curl's own `cacert.pem` (200 KB) in `ux0:data/` also verified, and is the fallback if a firmware lacks the system file.
  - `curl_global_init()` and a TLS handshake against OpenSSL 1.1.1t run fine on a `sceKernelCreateThread` thread.
- The server links libcurl (`curl` before `ssl` in `target_link_libraries`) for the `curl` builtin; `SceNet_stub` and `SceNetCtl_stub` were already there. libcurl and libssh2 never mix, and the client does not link it. The engine is `src/sshd_curl.c` (`sshd_curl_run()`), kept apart from `src/sshd_builtins.c` so the wget frontend (TASK-017.03) can reuse it; `cmd_curl` only parses flags and supplies `curl_resolve_out()`, which resolves a name through the path layer, checks the device is writable and that the parent directory exists.
- `wget` (`cmd_wget`, with its option parser in `src/sh_wget_args.c`) is a frontend over `sshd_curl_run()`, not a second client: it sets `follow` and `fail_http`, names the file by the URL unless `-O` gives one (an explicit `-O` wins over Content-Disposition because `choose_name()` checks `out_arg` first), and `-q` is `silent` plus `show_errors`. `sshd_curl_opts_t` carries `tool`, `insecure_flag` and `out_flag` so engine messages say `wget:` and name wget's own switches; a new engine message must use them rather than a literal `curl:`. `fetch_resolve_out()` serves both commands through a `fetch_ctx_t`. Device results (the Vita, home network, 2026-11-18): `wget` of the wifiturbo.suprx asset gave 51.6K with the release's SHA-1, as did `-q -O NAME` and `-O -` through ssh; hostile Content-Disposition values (`../../ux0/data/x`, `filename*=` with `%2F`) became bare names in the cwd under both `wget --content-disposition` and `curl -sJO`, `..` was refused, and `-O` beat the server's name; a 404 exited 22 with no file, a redirect loop stopped at 10 (47), a stalled body timed out at 30 s with no `.part`.
- How the engine keeps the poll loop alive: `curl_multi` with `curl_multi_perform()` each pass, `sh_session_yield()` and `sh_session_interrupted()` between passes, and `sh_server_poll_slice(50)` only when `curl_multi_wait()` reports nothing ready (sleeping on every pass capped throughput at one 16 KB buffer per 50 ms). Bounds: 15 s connect, `LOW_SPEED_LIMIT` 1 KB/s for 30 s, 10 redirects, 256 MB (`CURLOPT_MAXFILESIZE_LARGE` for a declared length, the write callback for an undeclared one). The resolver is libc's and blocks inside `curl_multi_perform()`; it cannot be bounded. The output file is opened lazily at the first body byte (so `-f` never creates one) as `NAME.part`, then `unlink` plus `rename` over the target, since an existing target is removed first and the platform rename has not been shown to replace one.
- Device results (the Vita, 2026-11-18, server thread's 512 KB stack, no overflow): `curl -LJO` of the wifiturbo.suprx release asset gave 52879 bytes with the release's SHA-1; hostile `Content-Disposition` values from a local test server (`../../ux0/data/x`, `..`, `%2F`-encoded, `ux0:` prefix) were stripped to a bare name or refused; `-f` on a 404 left no file; a redirect loop stopped at 10; expired and self-signed certificates failed with a sentence naming the host and `-k` bypassed them with a warning; a server that sent 10 bytes and stalled timed out at 30 s with exit 28 while a second connection still got its banner and a shell; an oversize `Content-Length` and a 256 MB undeclared stream both stopped with exit 63 and no `.part` left.

## Source quirks

- Two user apps and one updater, with explicit `add_executable` lists in `CMakeLists.txt`: the client (`ssh_client_vita`, entry `src/main.c`, links libssh2), the server (`ssh_server_vita`, entry `src/sshd.c`, links libssh with `-DWITH_SERVER`), and the minimal updater (`ssh_updater_vita`, `src/sshd_updater.c` plus `src/vpk_promote.c`). New `.c` files must be added to the right list by hand; nothing globs. The client list is `main.c`, `input.c`, `network.c`, `ssh_client.c`, `shell.c`, `text.c`, `menu.c`. The server list is `sshd.c`, `sshd_session.c`, `sshd_builtins.c`, `sshd_hostkey.c`, `sftp_server.c`, `sh_path.c`, `sh_alias.c`, `sh_env.c`, `sh_expand.c`, `sh_lineq.c`, `sh_listen.c`, `sh_defer.c`, `sh_chain.c`, `sh_exit.c`, `sh_grep.c`, `sh_headtail.c`, `sh_textops.c`, `sh_curl_name.c`, `sh_wget_args.c`, `sh_stdin.c`, `vita_shims.c`, `network.c`, `sshd_vpk.c`, `vpk_promote.c`, `vpk_zip.c`, `vpk_head.c`, `vpk_policy.c`, plus the generated `build/vpk_head_template.c`. `src/network.c` is shared by client and server; only server and updater share `src/vpk_promote.c`.
- Headers live in `include/`, sources in `src/`.
- Script filenames are snake_case — `render_tiles.sh`, `convert_png.py`, `gen_wordlist.py`,
  `smoke.sh`. No hyphenated filenames under `scripts/` or `assets/`: a new tool with a
  multi-word name takes underscores, like every other identifier in the tree.
- Each app packages its own tile: the client's `vita_create_vpk` reads `sce_sys/`, the
  server's reads `sce_sys_sshd/`; both pack to `sce_sys/` inside their own VPK, so only the
  source directory differs. The PNGs are generated — edit the SVG sources in `assets/` and
  re-render with `assets/render_tiles.sh`, never touch the PNGs by hand. That script is the only
  sanctioned way to make a tile: it renders with `rsvg-convert`, hands the 24-bit result to
  `scripts/convert_png.py` (a uv PEP 723 script — `uv run scripts/convert_png.py --check <png>`
  verifies without writing), which quantizes, strips ancillary chunks, and reads the file back
  before renaming it into place. Every tile PNG must come out an **8-bit palette PNG** or the
  installer rejects the whole VPK with `0x8010113D`: color type 3, bit depth 8, non-interlaced,
  and only `IHDR,PLTE,IDAT,IEND` — ImageMagick's default `tEXt`/`bKGD` chunks are rejected too.
  Check with `file tile.png` → must say `8-bit colormap`; `magick identify` cannot tell you this
  (it reports 8-bit depth per channel and calls a TrueColor render a `Palette` image). Note that
  "-depth 8" alone means 8 bits *per channel*, which looks correct and is not.
- Where the server's files live (`src/sshd_hostkey.c`, `data_dirs[]`): per device (`ux0`, `uma0`, `xmc0`, `ur0`, in that order) the host key and `authorized_keys` are in `<device>:/data/home/.ssh`, `$HOME` is `<device>:/data/home` (with `Downloads`, `Documents`, `Pictures` made at boot), and `sshd.log` stays in `<device>:/data/vitasshd`. The host key and `authorized_keys` searches look in `.ssh` first and the old `vitasshd` directory second, and boot renames the old files into `.ssh` when the new place lacks them; the second place is what keeps the fingerprint when a rename fails, so do not drop it. New keys are saved only to `.ssh`.
- With no `authorized_keys`, the server prints a generated **passphrase** instead: `PASSPHRASE_WORDS`
  words from a 1024-entry table in `src/sshd_hostkey.c`, concatenated with no separators. The table's
  three properties — exactly 2^10 entries (the generator indexes it with 10 random bits, so a short
  table is an out-of-bounds read), no entry a prefix of another (no separators means the reader segments
  it by eye, and a prefix pair renders two different secrets identically), and long enough to keep
  `password[64]` in `include/sshd.h` from truncating — are all checked by
  `python3 scripts/gen_wordlist.py --check`. Never edit the array by hand: edit `scripts/wordlist-pool.txt`,
  run `--emit`, paste, re-check. `--check` fails on a table the pool would not produce.
- In `taskfiles/setup.yml`, the `env -u CPPFLAGS -u LDFLAGS -u PKG_CONFIG_*` around
  libssh2's configure is load-bearing: a host Homebrew OpenSSL leaking into the probe
  passes the "Crypto library: OpenSSL" check, then fails to link against the 1.1.1 Vita
  port. Don't "clean that up".
- SFTP is libssh's stock server in `src/sftp_server.c`, adapted without forking the library. libssh 0.12.2 has no callback surface for overriding handlers (`message_handlers[]` and `process_client_message()` are static), so there are exactly two seams: `-Wl,--wrap` on the libc calls the stock handlers make (listed in `CMakeLists.txt`, server target only, translating through `sh_path.c` only while `active` is set), and `handle_rename()`, which answers a packet in `sh_sftp_data()` before the stock callback sees it. Adding a wrapped symbol means adding both the `__wrap_` function with its `__real_` declaration and the `-Wl,--wrap=` line.
- Opcodes the server overrides, and why. `chmod` and `chown` answer `SSH_FX_OP_UNSUPPORTED` (via `ENOSYS`) because the Vita has no permission or ownership model and a false OK makes the client believe it; `setstat` runs size, chmod, chown, then utimes in that order and stops at the first failure, so a setstat that combines permissions with times fails before the times are applied. The one exception is `handle_perm_setstat()`: a `SETSTAT` or `FSETSTAT` that carries only permission bits and asks for exactly the mode already reported (0644 for a file, 0755 for a directory) is answered OK, because that leaves the file as the client believes it is and it is what some clients send after a copy (no client has been observed sending it; OpenSSH 10.6's `scp -s` does not, see below); an `FSETSTAT` names a handle, not a path, so it is compared against the file mode. What `scp -s` actually sends after an upload is an `FSETSTAT` carrying only `SSH_FILEXFER_ATTR_SIZE` (flags 1, a 64-bit size, no permission bits, whatever the source file's mode), read off the wire on a device; `handle_size_fsetstat()` answers it OK when the open file already has that size. libssh keeps the handle's fd in a private struct, so the handler mirrors the head of `struct sftp_handle` from the pinned 0.12.2 and trusts the fd only when it is one of the server's own open files, else it falls back to unsupported; a libssh bump means rechecking that layout. Any other request, including one with times or a size that differs, still answers unsupported. A write, mkdir, rmdir or unlink on a read-only device answers `SSH_FX_PERMISSION_DENIED`: `writable_target()` sets `EACCES`, because libssh's `unix_errno_to_ssh_stat()` maps only `EACCES`/`EPERM` to that status and answers `EROFS` with a bare `SSH_FX_FAILURE`, which clients print as "Failure". Rename gets the same status from its own `EROFS` case in `reply_rename_error()`. `utimes` is honored for real (sceIoChstat sets times). `truncate` is translated and then read back, answering `ENOSYS` if the size did not change. `statvfs` answers `ENOSYS` (free space is an sceIo devctl, not a statvfs). `stat` and `lstat` normalize every entry to uid 0, gid 0, nlink 1 and a plain file or directory mode (0644/0755, 0444/0555 on read-only devices), so no client resolves a name that does not exist and nothing is ever reported as a symlink; `readlink` and `symlink` fail `ENOSYS` from `src/vita_shims.c`. `RENAME` and `posix-rename@openssh.com` are implemented in `handle_rename()` because the stock server leaves both unsupported: a different device answers `SSH_FX_FAILURE` ("cross-device rename not supported", never `OP_UNSUPPORTED`, which invites a retry by another route, and never a silent copy), a device root or read-only target is refused, plain `RENAME` onto an existing path fails as SFTP v3 requires, and `posix-rename` replaces a file by unlink-then-rename (not atomic) and never replaces a directory. `fstat` and every `fsetstat` not described above are left to the stock `process_unsupported`, which already answers honestly.
- SFTP transport rules, each learned the hard way on a device. (1) Nothing may block inside libssh from a callback: the session is attached to the poll event, and a blocking `ssh_channel_write` waits by polling the shared event context from inside the poll loop that called it, which stalls the session and strands others. So `sh_sftp_new()` sets the session non-blocking, `--wrap=ssh_channel_write` queues the stock handlers' replies, `drain_out()` hands libssh only what `ssh_channel_window_size()` allows, new requests wait while more than 128 KB of replies are queued, and `sh_sftp_pump()` runs on every poll-loop pass from `sh_session_pump()`. (2) `--wrap` also rewrites calls made inside libc itself: newlib's `opendir` is `open(path, O_DIRECTORY)`, so `__wrap_opendir` clears `active` around the real call or the already translated path is translated again and fails `ENOTDIR`. Any new wrapper that calls into libc has to ask whether libc calls another wrapped function. (3) Ending a session: on client EOF the server sends exit-status 0, EOF and close, then waits (3 s at most) for the channel to be closed before the transport is torn down; disconnecting early makes the client's ssh exit 255 and scp reports a failed copy. (4) libssh formats `ls -l` names with `ctime_r()` and passes the result to `asctime_r()` unchecked, and newlib's `localtime_r` returns NULL for a time sceRtc rejects, so every stat handed to libssh goes through `usable_time()`. (5) `ssh_channel_write` runs libssh's packet loop, so the client's next request can reach `sh_sftp_data()` in the middle of `drain_out()`; `drain_out()` sets `busy` while it writes so that request is only queued, because a nested `drain_out()` moves `out_off` under the outer call and bytes go out twice while others are skipped (a download desynchronizes past roughly 10 MB with no error logged).

## Server platform rules

The layering, bottom to top, is `sh_path.c` (POSIX path to device path), `sshd_builtins.c` (the command table), `sshd_session.c` (one SSH session), `sshd.c` (net bring-up, accept loop, poll loop, console). Each rule below comes from the platform, not from taste, and each looks like something worth "fixing".

- **One thread, one poll loop.** Everything (vita2d, the pad, the sockets, every session) is driven from `server_thread()`, so nothing is locked and nothing may block. There is no fork, so a command runs inside the server: the line editor only marks a line complete and `sh_session_pump()` runs it from the loop, never from a libssh callback. A running command cannot be interrupted by Ctrl-C, because noticing the keystroke needs the socket the command is blocking; walks are bounded by `MAX_DEPTH` and read limits instead. The thread is created with an explicit stack because a homebrew main thread's is too small for libssh's crypto and the tree walks.
- **Completed lines are queued, never overwritten.** The editor pushes a finished line into a per-session `sh_lineq_t` (`SH_LINEQ_MAX` 8 heap copies) and `sh_session_pump()` pops one per poll-loop pass, so a pasted block or lines typed while a long command runs all run, in order. A full queue refuses the new line with `sh: input queue full, line discarded` and keeps the earlier ones; the refused line is not added to history. Lines are echoed when typed, history and `!n` expand when the line is completed, and the prompt is written after each command (redrawn with the half-typed line when there is one). An LF directly after a CR is swallowed (`after_cr`), so a CRLF line runs once while every other empty Enter is a line of its own. Exec pushes its one command into the same queue, and the sftp subsystem is accepted only while the queue is empty. A client EOF with lines still queued (a piped script) sets `eof_seen` and the session ends after the last one runs, and a session ending on `exit` or a drained EOF first waits for libssh's output buffer to empty, because queued commands run back to back and the session is freed right after. Memory: about 2.1 KB idle per session (2 KB of it the deferred-echo buffer), at most 8 x `SSHD_LINE_MAX` (32 KB) more when every slot holds a maximal line.
- **A pipeline is sequential, not streaming.** `a | b | c` runs the segments one after another inside the one poll-loop pass: each segment but the last runs with `sh_write()` captured into a memory buffer (`sh_session_capture_start/_end`), and `sh_session_capture_end()` makes it the next segment's stdin. Both the capture and stdin are bounded by `SSHD_STDIN_MAX` (1 MB); a segment that produces more fails the pipeline with `sh: <cmd>: output too large for a pipe (limit N bytes)` and the later segments do not run. The `|` word must be a separate, unquoted word like `>` and `<`: a glued `a|b` stays one word and a quoted `"|"` is an argument. A `>` redirect on a segment is checked before the capture, so it wins and the next segment reads an empty stdin; `sh_eprintf` is never captured. A segment other than the last cannot change session state, as in a subshell: `exit` is skipped and the cwd is restored after `cd`. The status is the last segment's, and an empty segment (`| x`, `x |`, `x | | y`) is a syntax error (status 2) that runs nothing. The capture does not make a slow segment yield; a long walk yields for itself (next rule).
- **A long walk yields with `sh_session_yield()`.** A CPU- or I/O-bound builtin starves every other session, the accept path and the console unless it polls (`du /ux0` ran about 170 s on a device and a second ssh could not finish its banner). The tree walkers `rm -r`, `cp -r` and `du` call `sh_session_yield(s)` once per directory entry, next to `sh_session_interrupted()`, and `copy_file()` (behind `cp` and `mv`) calls it once per 64 KB chunk, since one large file is a long walk of its own; it runs one zero-wait `sh_server_poll_slice()` at most every 100 ms (`YIELD_INTERVAL_US`) and does nothing unless the session is inside `sh_session_pump()` (`in_pump`), so a call from a libssh callback never polls. A slice reads sockets and finishes handshakes; other sessions' commands still wait for the running one. `grep` has no directory walk, so it does not yield. A new builtin that loops over many entries or blocks on I/O for more than a moment must call `sh_session_yield()` in its loop. A slice also frees the slot of every other session whose transport libssh saw close (`slot_reap_closed()` in `src/sshd.c`, logged as `session <peer> dropped: ... (while a command ran)`), so a client that disconnects while a command runs does not hold one of the four slots until the command ends, and a command it had queued never starts. The running session's own slot is never freed from inside its command (`pumping_slot`). Only a closed transport frees a slot: a client's channel EOF does not, so an exec client that half-closes stdin keeps its command. The `poll: loop stalled` line skips a pump that took longer than its threshold, because a yielding command is not a suspend.
- **An exec session ignores the client's EOF.** `ssh host cmd` with no stdin sends EOF right behind the exec request, and treating it as the end of the session makes `sh_session_interrupted()` stop the command after its first chunk (`cat` of a large file came back as exactly 64 KB). Only sftp and shell sessions finish on EOF.
- **A command's output is paced by the client's window and by the socket.** A blocking `ssh_channel_write` waits with no timeout, twice over: for the client's window, and in its closing `ssh_channel_flush()` for the TCP socket to drain, which the Vita's small socket buffer reaches long before the client's ~2 MB window closes (a stalled `cat` parked the server for 11 minutes in a device run, accepting connections whose commands never ran). So `sh_session_pump()` sets the session non-blocking while a command runs (`in_pump`), and `chan_write_raw()` writes at most `ssh_channel_window_size()` bytes, first waiting in `wait_for_room()` until the window is open and `ssh_get_status()` shows no `SSH_WRITE_PENDING`. The wait runs `sh_server_poll_slice()` (one `ssh_event_dopoll` of 50 ms) so every session's socket is still read; memory held is one chunk plus what libssh already framed, not the output size. An exec command waits for libssh's buffer to empty after queueing exit status and EOF, because the session is freed right after: without it the tail of the output is cut off. A client that stays stalled for `WINDOW_STALL_S` (30 s), or whose session closed, marks the session finished, which stops the command and tears the session down. While one command waits, other sessions' commands and sftp pumps run only when it finishes. The wait is only legal from the pump, because `ssh_event_dopoll` is not reentrant from inside its own callbacks. A write from a libssh callback (the line editor's echo and the queue-full message, run by `on_channel_data()` with `in_cb` set) therefore never waits: with no command running it is a plain write on the blocking session (the banner, the idle prompt's echo), and while a command runs (`in_cb` and `in_pump`) `chan_write()` parks it in the per-session `sh_defer_t` (`SH_DEFER_MAX` 2048 bytes, a write that does not fit is dropped whole, as echo only) and `sh_session_pump()` sends it once the command ends, before the prompt or redraw. Waiting there is what wedged a session on a device (a line typed during `cat` of 1.4 MB parked the output until `stopped reading for 30 s`). `sh_write()` also sends callback output straight to the channel, so a line typed during `cmd > file` or a pipeline segment never lands in the file or the capture. sftp is unaffected; it paces itself in `drain_out()`.
- **One accept per readable-listening-fd event.** `accept()` is called by hand, once, in the poll callback (so the peer address is known before the handshake). Never turn it into a drain loop: the listening fd is blocking, so the second `accept()` with nothing queued parks the whole loop.

- **A dead listener is rebuilt by the loop, on the first accept failure.** A suspend and wake on another network kills the listening socket: the device log showed it readable once, `accept()` failing with `0x804101A3`, and then no event from it ever again, while a TCP connect to the port still succeeded and no banner came, until the app was restarted. So one accept failure is enough, not a count: a threshold would never be reached. `on_incoming()` only reports into `listener_health` (`src/sh_listen.c`), because the bind cannot be freed from inside its own poll callback; `server_loop()` runs `listener_rebuild()` after each `ssh_event_dopoll`, which drops the fd with `ssh_event_remove_fd`, frees the bind, waits for `sceNetCtlInetGetState` to say connected, and binds the same port again. Any failure there goes back through `sh_listen_failed()` for the backoff. Open sessions have their own sockets and are left alone. The displayed address is re-read on the power tick and logged as `address changed: A -> B`. The rebuild is a new socket only: if a device run shows the bind failing after a long outage, `sceNet` itself may need `bring_up_network()` again, which is not done yet. Device result (the Vita, 2026-11-19, suspended on the home network and woken on the office network, which was already connected): the log showed `accept failed: errno -2143223389 (0x804101A3)`, `address changed: A -> B`, `listener: rebuilding on port 22` and `ready: ssh any@<ip> -p 22 (listener rebuilt, fd 4)` in the same second, and the next connection logged in and ran a command with no restart. A second run (same day) switched a phone hotspot off with a shell open and back on: the open session dropped with `Socket error`, the address went to `0.0.0.0`, `listener: network is not connected; will retry` repeated with the backoff (1, 2, 4, 8 s, then the 30 s cap), and once the address returned the listener was rebuilt and new connections logged in, with no restart. Because the retry interval is already at its cap by then, the rebuild came about 27 s after the address returned.
- **The handshake is stepped from the poll loop, never run to completion in the accept callback.** libssh's `ssh_handle_key_exchange()` on a blocking session waits forever when no `SSH_OPTIONS_TIMEOUT` is set (nothing here sets one), so a socket that completes TCP and sends nothing used to park the one thread: later connections finished TCP in the kernel backlog (`nc -z` succeeded) and never received a banner, and a restart was the only cure. `on_incoming()` therefore sets the session non-blocking, calls `ssh_handle_key_exchange()` once, claims a slot with `handshaking` set and `accepted_us`, and `server_loop()` calls it again each pass (`handshake_step()`) until it returns `SSH_OK` or fails; `handshake_done()` puts the session back to blocking, which the rest of the session code assumes. A slot that has not logged in within `HANDSHAKE_TIMEOUT_S` (30 s, whether still in key exchange or at the login prompt) is freed with `reclaimed <peer>: no login within 30 s` in `sshd.log`. The cap stays `SSHD_MAX_SESSIONS` (4, a hardware limit): when the table is full, the newcomer evicts the longest-waiting slot that has not authenticated (`evicting <peer> ...`), and is refused only when all four have. Silent sockets therefore cannot keep a real client out. Verified on a device with `scripts/silent_sockets.sh` (8 silent sockets, then `ssh pwd` and 20 one-shots) and `scripts/smoke.sh exec`.
- **Callbacks return zero to accept.** For the pty, shell, exec and subsystem requests, 0 accepts and nonzero makes libssh send the failure. The service-request callback accepts the name `"ssh-userauth"` (not `"ssh-connection"`, which is only named inside the later userauth request); returning nonzero there makes libssh disconnect with code 11 and no error string, before any auth callback runs. Auth callbacks return `SSH_AUTH_SUCCESS` / `SSH_AUTH_DENIED`, not 0/1.
- **No `printf`, `puts` or `stdout`.** There is no terminal; libc stdout goes to the Vita's debug screen, not to the user. A builtin writes to its own channel with `sh_printf()` (stdout, redirectable with `>` / `>>`), `sh_eprintf()` (errors, always the terminal) or `sh_write()`. The Vita's own screen and `sshd.log` get `sh_console_log()`. `snprintf` into a buffer is fine.
- **The working directory is per session.** libc's cwd is a single static in newlib's `lib_a-fs.o` shared by the whole process, so one session calling `chdir()` would move every other session. Never call `chdir()` or `getcwd()`. A session's cwd and home live in `sh_fsctx_t`, read with `sh_session_get_fsctx()`; only `cd` and session setup write it, through `sh_session_set_cwd()`.

## Shell variables

- **Splitting and expansion are two steps on purpose.** `split_line()` runs on the whole line before anything executes, but `$NAME` is replaced by `expand_variables()` inside `run_command()`, after alias expansion and before redirects and globs, so `X=1 ; echo $X` sees the earlier item. To carry the quoting across, `split_line()` writes `SH_EXPAND_LITERAL_DOLLAR` (0x01) for a `$` that must stay text (single-quoted, backslashed, or right before a quote) and `sh_expand_word()` turns it back into `$`. A byte 0x01 typed by a client therefore comes out as `$`, which is harmless. Do not move the expansion into `split_line()`: it would run before an earlier chain item's assignment.
- **`quoted[i]` is not a bool any more.** It is 0 for an unquoted word, else `QUOTE_MARK(n)` where `n` is the count of unquoted bytes before the first quoted one; only `assignment_prefix()` reads the count, every other reader tests for zero. That count is what tells `X="a b"` (an assignment) from `"X=a b"` (a command name).
- **Fields come from IFS, and a value is never rescanned.** `sh_expand_word()` splits the value of an unquoted reference at `IFS` (unset means space, tab, newline; empty means none; whitespace characters merge and trim, any other IFS character ends a field alone and keeps empty ones) and never splits typed text, a double-quoted reference or an assignment value (`expand_variables()` passes `""` for the first `nassign` words). That needs a third quoting state, so `split_line()` writes `SH_EXPAND_QUOTED_DOLLAR` (0x02) for a `$` inside double quotes, which expands but does not split. Each field from a value is marked `QUOTE_VALUE` (bit 1 of `quoted[i]`): nonzero, so `extract_redirect()`, the pipe and chain checks and alias expansion treat it as quoted, but without `QUOTE_NOGLOB` (bit 0), so the glob loop still expands it, as in sh (TASK-020 AC4 was changed to say so). A word with typed quotes keeps its own flag and is not globbed, so `"$P"` is literal and `x"$P"` is too (per-word granularity, as for any quoted word). A split value may supply several words, including the command word.
- **Readonly lives in the table, enforced in the shell.** `sh_env_is_readonly()` is true for HOME, PWD, USER, LOGNAME, TMPDIR and for a variable the client supplied (`sh_env_lock()` after the pty or env request). `sh_env_set()` never refuses, because the server fills those names itself; only `set_variable()` and `cmd_unset()` ask.
- **A pipeline segment that is not the last restores the table** (`sh_env_snapshot()` before, `sh_env_restore()` after), like the cwd, since it is a subshell in sh.
- **Special parameters are lookups, not variables.** `parse_ref()` in `src/sh_expand.c` hands `$?`, `$$`, `$#`, `$!`, `$@`, `$*`, `$-` and `$0`..`$9` (and the braced forms, `${10}` included) to `expand_lookup()` as the one-character or digit name, and that function in `src/sshd_builtins.c` answers them: `?` from `sh_session_last_status()` (the session's `last_status`, 0 from `calloc`), `$` from `sh_session_id()` (a counter assigned in `sh_session_new()`, so concurrent sessions differ), `#` is `0`, `0` is `sh`, and the rest are unset. With no scripts, functions, jobs or options there is nothing to set them, so none of the unset ones can ever hold a value; do not add `set --` or `shift` without a reason. A double-quoted `"$@"` yields one empty word where sh yields none, because `run_command()` keeps any quoted word. `"$$"` arrives as two `SH_EXPAND_QUOTED_DOLLAR` bytes, which `special_char()` accounts for. The status is stored by `run_chain()` after each item that ran and by `sh_execute_line()` on every return, so `false ; echo $?` sees 1 and a syntax error or unknown command (2, 127) is seen by the next line. A skipped `&&`/`||` item leaves it alone, and a pipeline's status is its last segment's. TASK-031's `exit` with no argument reads the same field.
- Backticks are not recognised; they reach the command as text.

## The path layer

`include/sh_path.h` is the only place allowed to know how a POSIX path becomes a Vita device path (`/ux0/data/x` becomes `ux0:data/x`). The Vita has no unified tree, no root, and no symlinks; `sceIo*` understands only `dev:` prefixes.

- Builtins and SFTP handlers speak POSIX (`/ux0/...`, `~`, relative to the session cwd). Resolve with `sh_path_resolve()` or `sh_path_sce()`, and pass the resulting `sce` string to the libc call (`open`, `stat`, `opendir`, `unlink`, ...), which newlib maps onto `sceIo*`. Never build a `ux0:` string by hand.
- Normalize in POSIX space and translate once, immediately before the file call. `..` is applied against the component stack and clamps at the device root, so a relative path can never leave its device. Normalizing a `dev:` path instead is where `ux0:../vs0:` bugs live, because the sceIo spelling has no root to stop at. Never translate a path twice either: translating an already translated path is the cause of the `opendir` bug in the SFTP notes above.
- An unknown first component is `ENOENT`. Never fall back to a default device, because that turns a typo into a file on the wrong device. `/` is a synthetic listing of the device table (`SH_TARGET_ROOT`), not a directory: `sh_path_sce()` fails with `ENOTSUP` for it, and `cd /` is special-cased in `cmd_cd`.
- No symlink faking. There are none, so `readlink` and `symlink` fail `ENOSYS` and `lstat` never reports one; do not add a command that pretends otherwise.
- Check `dev->writable` before any mutation (`check_writable()` in `sshd_builtins.c`), so a write to `/os0` says "Read-only file system" instead of an opaque `sceIo` code. The table marks a device writable when unsure, because an error the user can read beats a false refusal they cannot work around.
- Removable devices (`sd0`, `uma0`, `xmc0`, ...) exist only while something is in them; `sh_device_present()` probes them.
- The helpers `sh_basename()`, `sh_join()`, `sh_parent()` and `sh_is_dot()` are pure string functions with no syscalls; use them rather than `strrchr`. Buffers are `SH_POSIX_PATH_MAX` / `SH_SCE_PATH_MAX` (1024), and every function returns `ENAMETOOLONG` rather than truncating.

## Platform metadata quirks

- **Directories are identified by `stat()` and `S_ISDIR(st.st_mode)`.** Newlib's `struct dirent` here has no `d_type` (so no `DT_DIR`); it carries `d_stat`, a `SceIoStat`, which nothing in this tree reads. Every directory walk calls `stat()` on the entry's resolved path.
- **There is no usable path-length constant.** `PATH_MAX` is not defined by `<limits.h>` plus `<dirent.h>` here, and `NAME_MAX` only arrives through `<sys/param.h>` (the sources carry an `#ifndef NAME_MAX` / `#define NAME_MAX 255` fallback; 255 is the POSIX minimum and FAT's long-name limit). Use `SH_POSIX_PATH_MAX` and `SH_SCE_PATH_MAX` for paths and `NAME_MAX + 1` for a single name, and keep buffers on the heap or small: a Vita thread's stack is whatever `sceKernelCreateThread` was given.
- **There are no permission bits, owners or link counts.** FAT `stat()` fills `st_mode` with the file type and nothing else, so formatting it directly prints nine dashes. `synth_mode()` in `sshd_builtins.c` builds 0755/0644 from the type, and drops the write bits on a read-only device; `normalise_stat()` in `sftp_server.c` does the same for SFTP (see the SFTP notes above).
- **Times can be unrepresentable.** `localtime_r()` returns `NULL` for a time `sceRtc` rejects (a synthetic stat's 0, a FAT entry with no date) and libssh does not check it. Pass times through `usable_time()` before they leave the server.
- **Free space is a devctl, not `statvfs`.** `df` uses `sceIoDevctl` with `0x3001` (`DEVCTL_GET_DEV_INFO`) and `psp2/io/devctl.h`; `statvfs` answers `ENOSYS`.
- **`strerror()` on a `sceNet` failure** may be a `0x80......` code that newlib cannot name; log the number, not just the text.
- The POSIX surfaces libssh references that the platform lacks (`dup2`, `waitpid`, uid/gid lookups, symlinks) are stubbed to fail `ENOSYS` in `src/vita_shims.c`. A new undefined reference at link time belongs there if it is a genuine absence, and gets a failure, not a fake success. The calls the Vita does have (`open`/`read`/`stat`/`opendir`/`rename`/`socket`/`poll`...) are NOT shimmed; newlib already maps them.

## Adding a builtin command

1. Write `static int cmd_<name>(sh_session_t *s, int argc, char **argv)` in `src/sshd_builtins.c`. It runs inside the server's poll loop: return an exit status (0 success, nonzero failure), keep it bounded, and never block on the network or sleep.
2. Resolve every path argument through `resolve_arg(s, "<name>", arg, &t)`, which fills an `sh_target_t` and prints the failure in the command's own voice. Use `t.sce` for the libc call, and `stat()` plus `S_ISDIR` for the type. Call `check_writable()` before anything that creates, changes or removes. For a path-less default use the cwd by passing `NULL`; bare `cd` passes `"~"` for home.
3. Output goes through `sh_printf()`, errors through `sh_eprintf()` in the form `<name>: <arg>: <strerror(errno)>`. The dispatcher speaks for the shell itself with an `sh:` prefix instead: `sh: <name>: command not found` (status 127), `sh: syntax error near unexpected token `|'` (status 2), and `sh: <file>: <reason>` for a redirect or `<` target. A builtin never prints those. No `printf`, no `chdir()`, no hand-built `ux0:` strings. A long walk checks `sh_session_interrupted()` and respects `MAX_DEPTH`.
4. Add a row to the `builtins[]` table at the bottom of the file, in alphabetical order (`help` prints the table in order). The row is `{"name", cmd_name, "usage -- one-line description"}`. Nothing else registers it, and `src/sshd_builtins.c` is already in the server's `add_executable` list.
5. Run `task build`, or `cmake --build build --target ssh_server_vita` for the server alone (see Build above). Compile and link is the only check available here; behavior is verified on a device.
6. If the command needs the network, read [`docs/vcmd.md`](docs/vcmd.md) first. `vcmd` is the only builtin that opens a socket and is the working example of doing it without freezing the poll loop: copy its `net_wait()` shape (zero-timeout `poll()` plus `sh_server_poll_slice()`, a hard deadline, non-blocking connect/send/receive, `getsockopt(SO_ERROR)` after a *successful* writability wait) rather than writing a bare `connect()`/`recv()`. That file also lists its error strings, saying which were confirmed on a device and which are source-only, and documents the plugin command surfaces it drives on ports 1338/1339.

## `vpk install` (the server's self-update and other titles)

- `vpk install [-r | --reinstall] <filename>.vpk` installs the vitasshd server over itself through the updater handoff, or any other title that is not running by promoting it directly (`--reinstall`, or `-r`, replaces an installed one), so a build reaches a device with `scp -s` plus one `ssh` command and no USB mount. What is allowed is decided by `vpk_decide()` in `src/vpk_policy.c`, host tested by `scripts/test_vpk_policy.py`: a malformed title, the updater title, `NPXS` system apps and a running title are refused, an installed title needs `-r`. The running check is `sceAppMgrGetIdByName()`, verified on a device against the server's own title; a running third-party title cannot be arranged there because the server is the one foreground app. The promoter call for a third-party title blocks the poll loop. The step-by-step is in [`docs/development.md`](docs/development.md) under "Install over SSH instead".
- The server is linked **UNSAFE** (`vita_create_self(... UNSAFE)`); a safe-mode app cannot see `ux0:app`, `ux0:patch` or the device info `df` reads. UNSAFE is also why the server now binds port 22 instead of falling back to 2222.
- `ux0:app/<TITLEID>` is read-only to the app even when UNSAFE, and a copy placed in `ux0:patch/<TITLEID>` is not used at launch. Both were tried on a device. The only route that installs is `scePromoterUtilityPromotePkgWithRif` on an unpacked package, which is what `src/sshd_vpk.c` does; do not reintroduce a file-copy install.
- The promoter refuses a running target (`0x80101114`). The server bundles `updater.vpk`
  (ROM000072, distinct from the earlier ROM000071 test bubble), stages the server in
  `ux0:data/vitasshd-update/server`, promotes the helper, closes the command's SSH channel,
  launches the helper and immediately exits. The helper targets only ROM000070 for shutdown,
  promotes the stage, records `result.txt`, and relaunches the server even on failure.
  `include/vpk_update.h` is the shared path contract. Never reuse VitaShell's `ux0:data/pkg`
  or `ux0:data/home/.ssh` (the host key and authorized_keys) for staging. The `ready` marker is one-shot:
  manually launching the updater must not replay an installation.
- The server VPK has an explicit dependency on the helper VPK target as well as its own
  SELF target; retain both so a helper change is bundled in the same build pass.
- The promoter needs `sce_sys/package/head.bin` in the package directory. Its template is `third_party/vitashell/head.bin` (VitaShell's, GPL-3.0, not covered by the repo's Unlicense), compiled in through `build/vpk_head_template.c`, which CMake generates at configure time. Do not edit the template, and keep its license file next to it.
- `opendir()` on a missing path answers `ENOTDIR`, not `ENOENT`: ask `stat()` whether something exists.
- `sh_printf` does not understand `%zu`; cast to `unsigned` and use `%u`.
- A rebuild needs a new `__DATE__ __TIME__` to be told apart on a device: `touch` is not enough because the task fingerprint ignores it, so `task --force build`, then read the `sftp: server code built` line in `sshd.log` (written when the first SFTP session starts).
